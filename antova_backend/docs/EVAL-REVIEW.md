# Evaluation review

Audit of how Antova measures extraction and leveling accuracy, as of 27 Nov 2026. It covers what
the existing evals prove, what they don't, and the order to close the gaps in.

## What runs today

| Eval | Command | What it measures | Result (27 Nov) |
|---|---|---|---|
| Mutation packs | `python -m antova_ingest.eval` | The deterministic pipeline (parse, verify, sweep, precedence, pricing) on 14 edge-case operators, using the **answer key as the locator** | 15/15 packs: 100% recall, status and pricing; 0 key differences |
| Locator on saved answers | `ANTOVA_LOCATE_PROVIDER=explabs EXPLABS_MODEL=gpt-6-luna python -m antova_ingest.locator_eval` | The model's recorded answers for TENDER-2026-402 and -417: quote verification, recall against the key, headline and cover claim, then the pipeline on those answers | 8/8 documents 100% recall, 0 rejected quotes; 56/56 cells match status and pricing |
| Engine unit and property tests | `python -m pytest`, `npm run test:unit` | Leveling math, Python and TS. New in Phase 1: Hypothesis invariants and a 200-tender Python ↔ TS parity check | All pass. Parity found one real bug, now fixed (negative headline counted as a price) |
| Live end-to-end | `node scripts/test-native-e2e.mjs <url>` | One real-model run of the Cloudflare built-in engine on the 402 sample | Passed 24 Nov in 66.9 s; Nordwerk lowest at €452,000 |

## Scorecard

| Dimension | Status | Evidence | Gap |
|---|---|---|---|
| Factual accuracy (extraction) | PARTIAL | locator_eval: 100% on 2 packs | Both packs are synthetic, generated by `samples/scenario*.py`, and the prompts were tuned on them. 56 cells say nothing about real vendor PDFs. |
| Context faithfulness / hallucination | COVERED | `verify` rejects any quote not on its page word for word; 0 rejected across 528 mutation quotes and 70 model quotes | None for quotes. Values are re-parsed from the verified quote, so a model can't invent a number the PDF doesn't contain. |
| Output structure validity | COVERED | Locator responses are schema-checked (`parseJsonObject`, `ExtractError`), and every parameter needs a candidate or `not_stated` | — |
| Leveling correctness | COVERED | Property tests, parity fixture, sensitivity parity, snapshot | Unit and scale bugs (kV, MVA, kW losses, k€) are not yet audited. The dimensional-analysis audit is blocked on the Trail of Bits plugin. |
| Escalation (knowing when to ask a human) | PARTIAL | Flags, `UNPRICED` and `MANUAL_INSPECTION_REQUIRED` exist; scanned_page raises 7 flags | No eval scores whether flags fire on the cells a reviewer would have caught. Expected flags aren't in `expected.json`. |
| Prompt injection | PARTIAL | `injection_text` mutation passes, but only with the answer-key locator | Never run against the real model. The mutation proves the pipeline ignores injected text, not that the model does. |
| Production path coverage | MISSING | — | The live Worker runs the **TS** built-in engine (`src/lib/native/llm.ts`, its own prompt). `locator_eval` scores the **Python** `ModelLocator`. The production extractor has one e2e run on one pack and no scored eval. |
| Third pack | MISSING | TENDER-2026-418 has PDFs and `expected.json` | Not in `locator_eval` `DEFAULT_PACKS`, and it has no saved model answers. |
| Extended parameter class | MISSING | `EXTENDED_PARAMETERS` in the TS ontology | No pack exercises it with the model. |
| Production monitoring | MISSING | Reviewer approve, override and reject rows are stored per cell | Nothing aggregates them. A reviewer override is the best free signal of an extraction error, and it's thrown away. |
| Cost and latency | PARTIAL | Token usage is recorded per call | Recorded cost shows $0.0000 for the saved explabs answers, so cost isn't priced for this provider. There's no latency budget or alert. |

**Verdict:** the deterministic half (verification, pricing, leveling) is well evaluated. The
model half is only checked on two synthetic packs through a code path production doesn't use.
The 100% figures are real, but they're not yet an accuracy claim about real tenders.

## Remediation, in order

1. **Score the production extractor.** Add a TS `locator-eval` over the same `expected.json` files, run in replay against recorded `gpt-6-luna` answers. Phase 2 work, since it touches the Worker path.
2. **Add pack 418 and the extended class** to the default eval set, and record answers for them once (paid, about cents per pack).
3. **Add expected flags to `expected.json`**, so escalation gets scored and not just counted.
4. **Run `injection_text` through the real model** in replay, so the guardrail is proven against the thing it guards.
5. **Turn reviewer decisions into a metric.** Share of cells overridden or rejected per tender and per parameter, shown on the governance page. This is the flywheel for real tenders.
6. **Get 3–5 real tenders (anonymised)** with a bid engineer's answer key. Until then, accuracy claims should say "on synthetic packs".
7. **Price explabs usage** in `api_cost_usd` and alert when a run exceeds a cost or latency budget.
